Anthropic Embeds Invisible Watermarks in All Claude Text Outputs

Important

Starting August 2, all new Claude models embed machine-readable watermarks into generated text, with C2PA-based provenance metadata on supported file types. The watermarks are invisible during normal reading and persist through copy-paste and some editing. The move responds to Article 50 of the EU AI Act and applies globally, not just in Europe.

Why it matters: If you use Claude to draft client content, proposals, or website copy, be aware that outputs now carry a detectable AI fingerprint. This doesn't prove authorship (Claude may have edited human text), but clients in regulated industries may ask about it. Consider disclosing AI-assisted content in your workflows.
via TechCrunch

Claude Code Auto Mode Becomes Default on August 14

Update

Anthropic will switch auto mode to the default permission setting for Claude Code on Pro, Max, and Team plans starting August 14. Auto mode uses a classifier to check each tool call for irreversible or destructive actions instead of prompting for manual approval. In testing with 1,053 users, auto mode caught 89% of harmful actions vs. only 13.6% by human review. Extra classifier tokens are now free.

Why it matters: This directly impacts your daily Claude Code workflow. Auto mode is faster and ironically safer than manual approval for most operations. If you have a pinned default, nothing changes automatically, but switching early lets you get comfortable before the rollout.
via TechCrunch

WordPress 7.1 RC2 Ships Today — Final Release August 19

Update

WordPress 7.1 Release Candidate 2 drops today (August 12), one week before the final release at WordCamp US on August 19. Since RC1, fixes have landed for the enforced iframe mode in block themes, React 19 experimental support, and 145+ editor and core updates. The release is led by Anne McCarthy.

WordPress 7.0.3 Security Release — Critical Pre-Auth XSS (CVE-2026-64638)

Security

WordPress 7.0.3 patches 12 vulnerabilities including a critical pre-auth reflected XSS on the login page (CVSS 8.9) that can chain into PHP code execution via the Plugin/Theme Editor. Also fixes privilege escalation on multisite, stored XSS flaws, SSRF, CSS injection, and email verification bypass. Affects WordPress 6.4 through 7.0.2. Fixes backported through 4.7.

Why it matters: This is a patch-now situation. The login-page XSS doesn't require authentication — an attacker only needs an admin to click a crafted link. If any client sites are still on 7.0.2 or below, update immediately. Auto-updates should have fired, but verify.
via Patchstack
