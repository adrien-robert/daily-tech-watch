Stories of the week

WordPress 7.1.5 fixes 20 security issues

What happenedWordPress 7.1.5 was released on 18 Nov as a security release. It fixes 20 issues, including an unauthenticated privilege escalation through Template Part block attributes that could lead to remote code execution, two SQL injections, and an unauthenticated stored XSS through shortcode attributes in comments.

Where it standsAs of 20 Nov, the release post says backports to every branch eligible for security fixes, through 4.7, are still in progress and ship as they become ready. It also says WordPress 7.2 RC 2 has been released with all applicable fixes, and that 7.2 is planned for 8 Dec. Source

Why it matters: Update every client site now, and check that sites on older branches have received their backport before assuming they are covered.

  • WordPress 7.1.5 fixes 20 security issues, including an unauthenticated flaw that could lead to RCE · Thu 19 Nov edition

Host-level patching: PHP and NGINX

What happenedOn 18 Nov, NGINX 1.31.9 and 1.30.7 fixed CVE-2026-123007, an HTTP/2 memory corruption bug present since 1.9.5, with four more flaws. The next day PHP 8.5.13, 8.4.28, 8.3.37 and 8.2.36 fixed 18 CVEs, seven rated Critical, which Patchstack says sit under WordPress and need a host update.

Where it standsAs of its 18 Nov report, The Hacker News says no attacks on the NGINX flaw were reported, CISA had not listed it, and a public proof of concept exists. It also says Ubuntu and Debian had not yet shipped fixed packages that day, and that turning off HTTP/2 is a temporary mitigation for two of the five flaws. Source

Why it matters: You cannot patch this yourself: ask each host whether it has moved to the fixed PHP and NGINX versions, and keep this on your list until they confirm.

  • PHP 8.5.13, 8.4.28, 8.3.37 and 8.2.36 fix 18 CVEs, seven rated Critical · Thu 19 Nov edition
  • NGINX patches critical HTTP/2 flaw that allows remote code execution · Thu 19 Nov edition

The Abilities API moves into everyday WordPress tools

What happenedACF 6.8.12, published on 19 Nov, turns the Abilities API on by default for the whole site and for every existing field group, post type and taxonomy. The same day a core developer note said WordPress 7.2 lets abilities declare required capabilities, and the AI team agreed on 18 Nov that abilities for 7.3 are built in core first.

Where it standsAs of 20 Nov, ACF's release post says field groups still need Show in REST API turned on before AI tools can read or update their fields, that settings already set in code stay locked, and that the acf/settings/show_settings filter hides the Features tab. Source

Why it matters: After updating ACF, client sites expose their structure to AI tools without you choosing it, so decide per site whether to switch that setting off.

  • ACF 6.8.12 adds a Settings page and turns the Abilities API on by default · Fri 20 Nov edition
  • WordPress 7.2 lets abilities declare required capabilities · Fri 20 Nov edition
  • WordPress AI team: abilities for 7.3 will be built in core first · Thu 19 Nov edition

Not in the daily editions

Quad9 leaves France after a court-ordered DNS blocking ruling

Cloudflare's 17 Nov post says Quad9 announced it will withdraw its free public DNS resolver from France after a French court imposed daily penalties for not blocking domains tied to alleged copyright infringement. It adds that a Belgian court order would penalise Cloudflare, Google and Cisco if they do not block through their public resolvers by early January 2027.

Why it matters: If you or clients use 9.9.9.9 in France, switch resolver settings before the withdrawal date of 24 Nov, which Quad9 gives.

via Cloudflare · published Tue 17 Nov
