Anthropic launches Claude Ship, with agents that fix and approve pull requests

🆕 New

Claude Ship bundles Code Review (generally available) with two beta agents: PR Steward, which fixes failing CI, merge conflicts and review feedback, and Claude Approvals, which approves changes under a policy written in the repository. It is rolling out to Team and Enterprise plans for GitHub repositories.

Why it matters: It needs a Team or Enterprise plan, so it only matters if you move to one. Anthropic advises starting in observe-only mode on a single repository, a sensible way to test it on a client project.

WordPress 7.2 will ship the /random/ redirect switched on by default

❗ Important

According to The Repository, core has no plans to make the endpoint opt-in before the final release on 8 Dec, despite developer pushback. Sites can turn it off with the wp_enable_random_content_redirect filter.

Why it matters: Decide before 8 Dec whether client sites should expose it. Disabling it is one line in an mu-plugin: add_filter( 'wp_enable_random_content_redirect', '__return_false' );

via The Repository · published Tue 24 Nov

WordPress 7.2 is fully compatible with PHP 8.6, minimum PHP stays at 7.4

🔄 Update

The core team said on 23 Nov that all known PHP 8.6 incompatibilities in core are fixed, as of Beta 5. WordPress 7.2 does not change the minimum supported PHP version.

Why it matters: Core is ready, but your plugins and themes are not covered. Test them on PHP 8.6 in staging before you move any client to it.

via Make WordPress Core · published Mon 23 Nov

Compromised developer account backdoors six WP connect plugins, stopped by a release hold

🔒 Security

Wordfence reports that a compromised developer account was used to push a remote-control backdoor into six WP connect plugins, including Air WP Sync and WP Sync for Notion. WordPress.org's release hold blocked it.

Why it matters: None of these are in your stack, but check client sites for any WP connect plugin and read the Wordfence post before updating them.

via Wordfence · published Mon 23 Nov

Google says its back button hijacking policy covers visits from social media too

🔄 Update

A new FAQ in Google's spam policies, added on 23 Nov, says the policy applies whenever the hijacking happens in a browser, not only on visits from Search. Sites can keep using ad platform code.

Why it matters: Check that client popups, exit-intent scripts and landing pages do not alter the browser history, whatever the traffic source.

via Search Engine Journal · published Mon 23 Nov

✨ Quick win

Add the wp_enable_random_content_redirect filter to an mu-plugin on one staging site and confirm /random/ stops redirecting, so you can roll it out before 7.2 ships on 8 Dec.
