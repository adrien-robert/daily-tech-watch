June 15 Claude Billing Split — 7 Days to Prepare

Deadline

Starting June 15, programmatic Claude usage (Agent SDK, claude -p, Claude Code GitHub Actions, third-party apps via Agent SDK) moves to a separate monthly credit pool. Credits: $20 (Pro), $100 (Max 5x), $200 (Max 20x). No rollover, no automatic overflow. Interactive use (chat, Claude Code terminal, Cowork) is unaffected. Enterprise seats get no credit by default.

Why it matters: If you use Claude Code in CI/CD pipelines or Agent SDK for automation, audit your usage NOW. Heavy users were previously accessing $300–600 of API-equivalent compute on a $20 Pro plan. That subsidy ends in 7 days. Enable overflow billing if you need uninterrupted automated workflows.

Claude Code Ultracode Mode & Dynamic Workflows

New

Claude Code's new "ultracode" effort setting combines xhigh reasoning with automatic workflow orchestration. Set /effort ultracode and Claude plans parallel subtasks via subagents, validates results, then presents a final answer. Proven use cases include codebase-wide bug hunts, profiler-guided optimization audits, security audits, and large migrations spanning thousands of files. Note: consumes substantially more tokens than standard sessions.

Why it matters: This is a game-changer for WordPress agency work. Run a full security audit of a client's plugin codebase, or refactor a large Bricks Builder project, in a single ultracode session — Claude handles the parallelization automatically.

Kirki Plugin CVE-2026-8206 (CVSS 9.8) — Wordfence Free Coverage Arriving Today

Security

A critical privilege escalation vulnerability in the Kirki Freeform Page Builder plugin (versions 6.0.0–6.0.6) allows unauthenticated attackers to take over administrator accounts via a flawed password reset mechanism. Active exploitation confirmed — Wordfence blocked 222+ attempts within 24 hours of disclosure. Wordfence free users are scheduled to receive firewall rule protection today, June 8. Patch available: upgrade to Kirki 6.0.7 immediately.

Why it matters: CVSS 9.8 — this is as critical as it gets. If any of your client sites use Kirki, update to 6.0.7 immediately. After patching, force-logout all users and require password resets, especially for admin accounts. Check if any of your sites were running vulnerable versions since June 2.
